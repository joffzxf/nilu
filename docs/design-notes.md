# 逆旅 · 设计笔记

这篇记录「为什么是这些数字、这些交互、这句话」，给以后的版本和开发日志留一份底稿。

---

## 1. 一句话规则

> 光点只能向右。按顺序完成方向键指令，斜率会抬高一点。六十年太长，这里只有六十秒；轨迹下的面积就是成绩。

玩家只需要理解三件事：

1. **箭头要按顺序按对。**
2. **按对会让坡度变陡。**
3. **时间到了，线下面的面积就是分数。**

其他都不解释，让画面自己说。

---

## 2. 一局的节奏

| 时间 | 发生什么 |
| --- | --- |
| 0s | 三、二、一，光点从左侧出发，贴地 |
| ~0.8s | 第一组 2 键指令出现 |
| 5–20s | 指令逐渐变长，斜率开始可见 |
| 20–45s | 进入「复利区」：早期抬升开始放大成面积 |
| 45–60s | 指令 6–7 键，窗口很紧；面积曲线变陡 |
| 60s | 结束，面积填充，结算 |

一局只有 60 秒，是因为：

- 够短，适合分享和重复挑战；
- 够长，能让「早期努力」和「后期努力」的差距显现；
- 和「一生」形成比例隐喻，但不至于让人真的坐一小时。

## 3. 数值

### 3.1 斜率

```text
room = max(0, 1 - slope / 2.6)
gain = 0.085 × room × (1 + min(combo, 10) × 0.012)
slope = min(2.6, slope + gain)
```

- 起始斜率 0，轨迹贴地。
- 越接近上限 2.6，单次提升越小。
- 连击有很小的加成（最多 12%），鼓励不要断。
- 上限保证画面不会飞出屏幕，也让「接近满分」有可见的天花板。

### 3.2 面积

```text
dx = 100 / durationTicks
y += slope × dx
area += y × dx
```

- 面积是 `∫ y dx`，用固定 tick 的矩形积分近似。
- 服务器和浏览器跑同一份代码，所以结果一致。
- 结算显示四舍五入后的整数。

**为什么面积比「最高斜率」好？**

最高斜率只记录一个瞬间；面积记录「你抬着头走了多久」。早期的一次抬升会被后面所有时间放大，晚期的抬升只影响一小段。这个数学事实本身就是游戏想说的话。

### 3.3 指令难度

```text
len = min(7, 2 + floor(level / 6))
perKeyMs = max(130, 300 - level × 4)
windowMs = max(1100, len × perKeyMs + 520 - level × 6)
```

- 前 5 次成功都是 2 键，给玩家建立节奏。
- 第 6 次开始变 3 键，之后每 6 次多一键。
- 到 30 次左右是 7 键，给键时间约 130–180ms/键。
- 窗口有一个 1100ms 下限，避免高等级瞬间变成不可能。

### 3.4 喘息

连续失误会触发：

```text
mercy = min(3, floor(missStreak / 2))
len = max(2, baseLen - mercy)
window = baseWindow × (1 + min(0.4, missStreak × 0.07))
```

第一次失败不会立刻变简单；连续两次、四次、六次，才逐步放宽。

理由：手慢的玩家不应该被锁死在「超时 → 更长 → 更超时」的循环里。游戏可以难，但不能让人无事可做。

### 3.5 本地模拟的分数带

60 秒，固定按键间隔的粗略模拟（不是人类样本，只是调参参考）：

| 操作水平 | 面积 |
| --- | --- |
| 脚本级 / 极熟 | 9,000–10,500 |
| 熟练 | 6,500–8,500 |
| 普通 | 4,000–6,000 |
| 偏慢 | 1,300–4,000 |
| 完全跟不上 | 0–1,000 |

第一名 10,182、第二名 9,414 的演示数据，是脚本按 70ms 间隔打出来的，用来验证上限和榜单视觉，不代表人类上限。

## 4. 交互

### 4.1 为什么用方向键

- 四个方向，不需要教学。
- 左右手都能按，长序列有「打字感」。
- 和「走」的意象一致：上、下、左、右，都是路。

### 4.2 为什么指令显示全部，而不是一个一个出

- 一次显示整组，玩家可以规划手指。
- 当前键高亮，降低记忆负担。
- 长序列看起来有压迫感，这是难度的一部分。

### 4.3 为什么错误只中断当前组

- 如果错误扣高度，玩家会害怕尝试，游戏变成「别犯错」而不是「往前走」。
- 现在错误只损失时间：这一组作废、进入喘息、下一组重来。
- 结算文案：「高度没有丢，只是少走了一段。」

### 4.4 暂停

- `Esc` / `P` / 右上角暂停。
- 暂停时 tick 不推进，恢复后窗口还在原处。
- 页面切到后台会自动暂停。
- 暂停是必要的：60 秒里可能有人敲门。但暂停不会让分数变高，只是把真实时间暂停。

### 4.5 手机

- 四个大按钮，放在拇指可及的位置。
- 指令区仍在下方，和按钮分离，避免遮挡。
- 窄屏隐藏「剩余时间」大字，把空间留给轨迹和指令。

## 5. 视觉

### 5.1 方向

不是霓虹赛博，也不是像素复古，而是「一张会动的宣纸」：

- 近黑底，暖白字，琥珀色光。
- 宋体做大标题，黑体做信息。
- 朱砂印章作为品牌符号。
- 轨迹像墨线，成功像落笔，失误像纸上的一个小红点。

### 5.2 为什么留这么多黑

黑是「还没有走的路」。

HUD 只保留四个数：面积、斜率、连续、剩余。指令卡只保留一组箭头和一条时间线。结算页只保留分数、四个统计、一句话。

信息越少，玩家越容易把注意力放在那条线上。

### 5.3 动效

- 光点呼吸、成功粒子、失败红屑、面积渐显。
- 所有动效都可以被 `prefers-reduced-motion` 关掉。
- 声音是合成的：按对是上行音阶，完成是和弦，失误是低音，结束是四音长和弦。
- 没有音频文件，首屏不需要加载任何媒体。

## 6. 文案

### 6.1 标题

「逆旅」取自：

- 李白：「天地者，万物之逆旅也；光阴者，百代之过客也。」
- 苏轼：「人生如逆旅，我亦是行人。」

两个字都指向同一件事：**人只是路过。**

### 6.2 结算

- 「此程已尽」
- 「一次也没有踏空。」/「踏空 N 次。高度没有丢，只是少走了一段。」
- 「最后三分之一的路，贡献了 X% 的面积。越往后，每一秒越重。」
- 「这些面积，有意义吗？」→「没有。它只证明，你曾把六十秒走成这样。但轨迹留下来了。」

最后这一问是整件作品的题眼。

游戏没有回答「人生有没有意义」，它只是把「努力 → 成就 → 数字」这条链路完整地摆出来，然后问一句：**然后呢？**

### 6.3 不说的话

- 不说「努力就会成功」。游戏只保证「努力会改变轨迹」。
- 不说「分数不重要」。分数当然重要，否则不会做排行榜。
- 不说「看淡一切」。那太轻巧了。
- 只问一句，然后让玩家自己走下去。

## 7. 排行榜

### 7.1 为什么所有账户都上榜

包括 0 分和没玩过的人。

- 如果只展示前 50 名，榜单是「赢家榜」。
- 如果所有人都出现，榜单是「同行者名单」。
- 0 分的人也在走，只是还没抬头。

### 7.2 为什么取「最好的一局」

- 一局 60 秒，玩家会反复挑战。
- 取最好成绩，让每一次尝试都有意义。
- 也避免「刷局数」压过「打得好」。

### 7.3 周榜

- 周一 00:00（Asia/Shanghai）重置。
- 给后来者一个重新开始的机会。
- 总榜记录「曾经走过多远」，周榜记录「这周还在不在走」。

## 8. 已知的未解问题

1. **手慢的人会不会太挫败？** 喘息机制是缓解，但还需要真实玩家测试。
2. **7 键是不是太长？** 目前只到 7；如果多数人卡在 5，考虑降到 6 或延长窗口。
3. **手机拇指操作和键盘的公平性**：同一排行榜里，触屏天然慢。后续可以考虑分设备榜，或给触屏更宽的窗口（但会破坏「同一套规则」的纯粹性）。
4. **脚本上限**：70ms 间隔已经能到 10k；人类上限可能 6–8k。排行榜前排会被脚本占据，这是回放机制无法解决的。
5. **「面积」是否该除以时间**：现在面积随时长增长；如果以后做不同时长的模式，需要归一化。

---

## 9. 一句话

**让努力可见，让失败可承受，让数字被记录，然后问一句：这些数字，真的算数吗？**
